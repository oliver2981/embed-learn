## 一、整型

### 1. 四种整型与字节数

| 数据类型 | 32 位系统（如 32 位 Windows/Linux） | 64 位系统（LP64，如 Linux/macOS） | 64 位系统（LLP64，如 Windows） |
| :--- | :---: | :---: | :---: |
| **`short`** | 16 位（2 字节） | 16 位（2 字节） | 16 位（2 字节） |
| **`int`** | 32 位（4 字节） | 32 位（4 字节） | 32 位（4 字节） |
| **`long`** | **32 位（4 字节）** | **64 位（8 字节）** | **32 位（4 字节）** |
| **`long long`** | 64 位（8 字节） | 64 位（8 字节） | 64 位（8 字节） |

> 记法：`short` 恒定 2 字节、`int` 恒定 4 字节、`long long` 恒定 8 字节，**只有 `long` 跟着系统变**。所以在 Windows 上写 `long` 并不比 `int` 大，想稳定用 8 字节就写 `long long`。

### 2. 格式符对应表

| 类型 | 输出 | 输入 | 备注 |
| :--- | :---: | :---: | :--- |
| `short` | `%hd` | `%hd` | |
| `int` | `%d` | `%d` | 最常用 |
| `long` | `%ld` | `%ld` | 字面量要加 `L` 后缀：`1000L` |
| `long long` | `%lld` | `%lld` | 字面量加 `LL` |
| `unsigned int` | `%u` | `%u` | 无符号，不打印负号 |
| `sizeof` 的返回值 | `%zu` | — | `sizeof` 返回 `size_t`，用它最规范 |

> 为什么 `long` 要写 `1000L`：不加后缀的 `1000` 默认是 `int`，赋给 `long` 时会先发生一次隐式转换。加 `L` 是明确告诉编译器"这个字面量本身就是 long"。

### 3. 整数运算的规矩

**整数算整数，结果还是整数。**

- `7 / 2` 得 `3`，小数部分直接丢掉，**不是四舍五入**
- `7 % 2` 得 `1`，`%` 只能用于整型；`7.5 % 2` 直接编译报错
- 溢出会"绕回"：`int` 最大值加 1 变成负数（计划里的 `INT_MAX + 1` 实验就是看这个）

## 二、实型（小数）

### 1. 三种小数类型

| 类型 | 中文名 | Windows 字节 | 有效数字 | 输出 | 输入 |
| :--- | :--- | :---: | :--- | :---: | :---: |
| `float` | 单精度 | 4 | 约 6~7 位 | `%f` | `%f` |
| `double` | 双精度 | 8 | 约 15~16 位 | `%f`（写 `%lf` 也行） | **必须** `%lf` |
| `long double` | 长双精度 | 各平台不同（MSVC 8 / MinGW 16） | 更多 | `%Lf` | `%Lf` |

两个容易记错的点：

1. **字面量后缀**：`float a = 3.14F;` 的 `F` 不能省。不写后缀时 `3.14` 默认按 `double` 处理，赋给 `float` 会发生一次隐式转换，编译器可能给"精度损失"警告。
2. **`%f` 默认打印 6 位小数**：`1.93` 打印出来是 `1.930000`。想控制位数写 `%.1f`（1 位）、`%.2f`（2 位）。

> 注意：6 位是**显示**位数，不等于这 6 位都准确。`float` 只有约 6~7 位有效数字，第 7 位往后基本是误差噪声 —— 所以"精确到小数点后六位"这个说法要打个折。

### 2. 小数运算的规矩

**小数算小数，整数和小数一起算还是小数。**

| 表达式 | 结果 | 说明 |
| :--- | :---: | :--- |
| `1 / 2` | `0` | 两个都是整数，整除 |
| `1.0 / 2` | `0.5` | 有一个是小数，结果就是小数 |
| `5 + 2.5` | `7.5` | 整数 + 小数 = 小数 |

> 记法：**想要小数结果，参与运算的数里至少要有一个是小数。**

另一个必须接受的事实：**小数之间的运算可能不精确**。因为二进制没法精确表示 `0.1` 这类十进制小数，`0.1 + 0.2` 实际算出的是 `0.30000000000000004`。所以比较两个小数是否相等，不能直接写 `a == b`，要比较差值。

## 三、字符型

- `char` 占 **1 个字节**，存的是字符的编码（ASCII 码）
- 单引号包一个字符就是字符常量：`'s'`、`'@'`、`'5'`
- 注意 `'5'` 和 `5` 不是一回事：`'5'` 是字符，值是 53；`5` 是整数 5

### 字符串到底占多少字节

```c
char str[10];      // 占 10 个字节
"aaa"              // 占 4 个字节
```

`"aaa"` 只有 3 个字符，为什么占 4 字节？因为字符串结尾有一个看不见的结束标记 `'\0'`（空字符），编译器会自动补上。

| 写法 | 含义 | 占字节 |
| :--- | :--- | :---: |
| `'a'` | 一个字符 | 1（`char`） |
| `"aaa"` | 3 个字符 + `\0` | 4 |
| `char str[10]` | 10 个字符的抽屉 | 10 |

> 记法：`char str[10]` 是 10 个抽屉；装 `"aaa"` 只用掉 4 个（a a a \0），剩下 6 个空着。

## 四、标识符

凡是自己起的名字 —— 变量名、函数名 —— 都是标识符。

1. 只能由**字母、数字、下划线**组成
2. **不能以数字开头**：`a1` 可以，`1a` 不行
3. 不能是**关键字**（`int`、`return`、`if` 这类系统保留字）
4. 区分大小写：`Sum` 和 `sum` 是两个不同的名字
5. 名字要能看懂：`score` 比 `a` 好

## 五、数值拆分公式

要把一个整数的每一位单独拆出来，靠 `/`（丢低位）和 `%`（取低位）配合：

| 想要 | 公式 | 例：`n = 1234` |
| :--- | :--- | :---: |
| 个位 | `n % 10` | 4 |
| 十位 | `n / 10 % 10` | 3 |
| 百位 | `n / 100 % 10` | 2 |
| 千位 | `n / 1000 % 10` | 1 |

> 记法：**先除后取余** —— 除法把高位留住、把不需要的低位切掉，取余再把目标位抠出来。

## 六、类型转换

### 1. 隐式转换（编译器自动做）

**小范围的和大范围的一起算，小的自动提升为大的，然后才运算。**

从小到大排：

```
char < short < int < long < long long < float < double
```

两条具体规则：

1. 混合运算时，小范围类型自动提升为大范围类型：`int` 和 `double` 相加，`int` 先变成 `double`
2. `char` / `short` 参与运算时，**先提升为 `int` 再算**，不会直接在 1 字节里算

### 2. 强制转换（自己动手）

**大的赋值给小的，必须强制转换，否则编译器报警告甚至直接报错。**

```c
int n = 40000;
short i = (short)n;    // 强转：只保留低 16 位
```

- 本质是**截断**：把超出目标类型范围的高位丢掉，取低 16 位
- 不是四舍五入，也不做范围检查。`40000` 塞进 `short` 会变成 `-25536`（超出上限就绕回负数）

## 七、自增自减

| 写法 | 名字 | 顺序 | 例（`a` 初始为 5） |
| :--- | :--- | :--- | :--- |
| `b = a++` | 后缀 | **先用后加**：先把原来的值给 `b`，`a` 再 +1 | `b = 5`，`a` 变 6 |
| `b = ++a` | 前缀 | **先加后用**：`a` 先 +1，再把新值给 `b` | `a` 变 6，`b = 6` |

### 一个表达式里出现多个 ++ 会怎样

在 Windows（MSVC）下实测：**前缀优先级高于后缀** —— 前缀先统一自增/自减，再把结果拿来用；后缀统一先用原值，等整个表达式算完再自增。

在 Linux（GCC）下实测：**前后缀优先级相同，从左到右依次运算**。

两种结果可能不一样：

```c
int a = 5, b;
b = a++ + ++a;    // MSVC 与 GCC 得到的结果不同
```

> 结论：**C 标准没有规定同一个表达式里多个自增的求值顺序**，所以这是"编译器相关"的坑，不能当规律记。生产代码里一个表达式只改一个变量，别写 `a++ + ++a`。

## 八、三元运算符

```c
关系表达式 ? 表达式1 : 表达式2;
```

- 条件成立 → 取**表达式1**
- 条件不成立 → 取**表达式2**

经典用法，求绝对值：

```c
number = number >= 0 ? number : -number;
```

> 记法：`?` 前是问题，`?` 后是"是"的答案，`:` 后是"否"的答案。

## 九、运算符优先级（补充）

> 对齐学习计划的运算符部分，按从高到低排，**同一行内从左到右**。记不住就加括号，括号永远最优先。

| 优先级 | 运算符 | 说明 |
| :---: | :--- | :--- |
| 1 | `()` `[]` `.` `->` | 括号、数组下标、成员 |
| 2 | `!` `~` `++` `--` `+`(正) `-`(负) `(类型)` `sizeof` | 单目运算符，右结合 |
| 3 | `*` `/` `%` | 乘除取余 |
| 4 | `+` `-` | 加减 |
| 5 | `<<` `>>` | 移位 |
| 6 | `<` `<=` `>` `>=` | 关系比较 |
| 7 | `==` `!=` | 相等判断 |
| 8 | `&&` | 逻辑与 |
| 9 | `\|\|` | 逻辑或 |
| 10 | `?:` | 三元，右结合 |
| 11 | `=` `+=` `-=` `*=` `/=` `%=` | 赋值，右结合 |

两个最常踩的：

- `a = b = 5` 能连写，因为赋值是**右结合**，从右往左算
- `x = a > b ? a : b` 不用加括号，因为 `?:` 的优先级低于比较，比较会先算

`size.c` 里这段值得背下来，以后测任何类型都套它：

```c
#include <stdio.h>

int main()
{
    long C = 1000L;          // L 不能省，否则会走隐式转换
    printf("%ld\n", C);      // 8 字节下正常打印
    printf("%zu\n", sizeof(C));     // sizeof(long) 在 Windows 上是 4
    printf("%zu\n", sizeof(long));

    unsigned int a = 100;    // 无符号整数，只能存非负数
    printf("%u", a);
    return 0;
}
```

## 十一、今天踩的坑

1. **`%.1f` 写成了 `.1%f`** —— 格式符里的 `%` 必须写在最前面，`%.1f` 才是"保留一位小数"。写成 `.1%f` 会打出莫名其妙的结果。
2. **`scanf` 忘记写 `&`** —— `scanf` 需要拿到变量的**地址**才能把输入写回去，所以 `&a`、`&b` 不能漏。（`&` 到底拿的是什么，预习指针时就能彻底搞清楚。）
3. **`printf` 的格式符必须和值的类型配对** —— `scanf.c` 里 `printf("%d\n", a + b)` 这一行有隐患：`a` 是 float、`b` 是 int，`a + b` 的结果是 **float**，用 `%d` 打印会输出垃圾值。应改成 `%f`。
