# Day 1｜数据与常量

> 目标：分清 C 语言里的数据有哪几类，并知道 `printf` 该用哪个格式符把它们打出来。

---

## 一、四类基本数据

| 类型 | 判断标准 | 举例 | 格式符 |
| :--- | :--- | :--- | :---: |
| 整型short； int ；long ；long long | 整数，没有小数点 | `10`、`-10` | `%d`（long是ld ；long long是lld） |
| 实型（浮点）float | 带小数点（或带指数）的数 | `1.93`、`.857`、`97.`、`2.5e2` | `%f` |
| 字符char | 单引号里的**一个**字符 | `'s'`、`'@'`、`' '` | `%c` |
| 字符串char str[占用内存]C语言没有string | 双引号里的一串字符 | `"hello"`、`""` | `%s` |

### 1. 整型

| 数据类型        | 32位系统 (如32位Windows/Linux) | 64位系统 (LP64模型，如Linux/macOS) | 64位系统 (LLP64模型，如Windows) |
| :-------------- | :----------------------------- | :--------------------------------- | :------------------------------ |
| **`short`**     | 16 位 (2字节)                  | 16 位 (2字节)                      | 16 位 (2字节)                   |
| **`int`**       | 32 位 (4字节)                  | 32 位 (4字节)                      | 32 位 (4字节)                   |
| **`long`**      | **32 位 (4字节)**              | **64 位 (8字节)**                  | **32 位 (4字节)**               |
| **`long long`** | 64 位 (8字节)                  | 64 位 (8字节)                      | 64 位 (8字节)                   |

直接写出来的整数就是整型，正负都算：`10`、`-10`、`0`。

### 2. 实型（三种写法）

实型的共同特征是"含小数点或含指数"，写法可以偷懒：

| 写法 | 值等于 | 说明 |
| :--- | :---: | :--- |
| `.857` | 0.857 | 整数部分省略，不写也行 |
| `97.` | 97.0 | 小数部分省略，只留小数点 |
| `2.5e2` | 250 | 科学计数法，`e2` 表示乘 10 的 2 次方 |

### 3. 字符

- 用**单引号**包住一个字符：`'s'`、`'@'`、`'9'`。
- 空格本身也是一个字符，必须写成 `' '`；引号里什么都不写（`''`）是**语法错误**。
- 一般用单个英文字母、数字或符号；换行这类特殊字符写成转义形式，如 `'\n'`。

### 4. 字符串

- 用**双引号**包住一串字符：`"hello"`、`"我今天真的cool"`。
- 双引号里什么都不写也是合法的，那就是一个**空字符串** `""`（长度为 0）。

> 记法：单引号 = 一个字符，双引号 = 一串字符，别混用。

## 二、printf 怎么用

```c
printf(参数1, 参数2);
```

- **参数1**：输出内容，必须以**字符串**形式出现（双引号包住）。不写双引号会编译报错。
- 参数1 里的 `%d` / `%f` / `%c` / `%s` 是**占位符**，会被后面的参数依次替换。
- **参数2 及以后**：真正要输出的数据，个数和占位符一一对应。

```c
#include <stdio.h>

int main()
{
    /* 整型   %d
       实型   %f
       字符   %c
       字符串 %s */
    int a = 10, c = 30;//变量在使用前一定要赋值
    int b = 20;
    printf("a+b=%d\n", a + b); //a+b=30
    printf("%f\n", 1.93);              // 1.930000
    printf("我今天真的%s\n", "cool");   // 我今天真的cool
    printf("%d", 010);//8 2进制的话就是0b开头 16进制的话就是0x开头
    return 0;
}
```

运行结果：

```text
1.930000
我今天真的cool
```

> `%f` 默认保留 6 位小数，所以 `1.93` 会打印成 `1.930000`。想控制位数就用 `%.2f`（保留两位）。

## 四、今天踩的坑

1. **忘记写分号** —— 每条语句结尾必须是 `;`，漏了会报 `expected ';'` 之类的错误。写完一行先扫一眼行尾。
2. **占位符和类型要配对** —— `%d` 配整型、`%f` 配实型、`%c` 配字符、`%s` 配字符串。
3. **单双引号不能混** —— `'s'` 是字符，`"s"` 是字符串，格式符用错会读出奇怪的值。

## 五、补充：常量与变量的规矩

> 对齐学习计划 D1 的"变量与常量、关键字与标识符命名"，先把概念摆在这儿，学到时对照。

### 常量（运行中不能改的量）

| 形式 | 写法示例 | 说明 |
| :--- | :--- | :--- |
| 字面常量 | `10`、`1.93`、`'s'`、`"hello"` | 直接写出来的值，就是第一节那些 |
| 宏常量 | `#define PI 3.14159` | 预处理阶段做文本替换，没有类型 |
| const 常量 | `const int MAX = 100;` | 有类型、编译期检查，推荐用这个 |

### 标识符命名（变量名、函数名都算）

1. 只能用字母、数字、下划线，且**不能以数字开头**：`a1` 可以，`1a` 不行。
2. 区分大小写：`Sum` 和 `sum` 是两个不同的名字。
3. 不能用关键字（`int`、`return`、`if` 这些系统保留字）。
4. 名字要能看懂：`score` 比 `a` 好。

## 七、附：中文乱码排错（环境搭建踩坑）

> 对应学习计划 D1 的"配好 VS Code + MinGW-w64"。这块卡了好几轮，结论记下来，以后换机器照做。

### 现象

`printf("我今天真的%s", "cool")` 打印出来是：

```text
1.930000
鎴戜粖澶╃湡鐨刢ool        ← 乱码（典型形态：鎴 / 戜 / 粖 / 涓枃 / 锟斤拷）
```

### 根因：三个环节里有两端对不上

| 环节 | 实际编码 | 说明 |
| :--- | :--- | :--- |
| ① 源码存盘 | UTF-8 | VSCode 默认就存 UTF-8 |
| ② 编译器输出 | UTF-8 | gcc 默认把源码里的中文字面量**原样**编成 UTF-8 字节 |
| ③ 终端解码 | **GBK(936)** | VSCode 集成终端按打开那一刻的系统码页解码 |

①、② 都是 UTF-8，③ 是 GBK —— 错位就出在 ② 和 ③ 之间。所以问题既不在 VSCode 界面，也不在代码写错。

### 怎么判断（别靠肉眼猜）

```powershell
chcp                                   # 看码页：936 就是 GBK 通道
cmd /c "prog.exe > out.bin"            # 用 cmd 重定向拿原始字节
```

| 编码 | 中文的字节形态 | 例 |
| :--- | :--- | :--- |
| UTF-8 | 三字节一组 | `E4 B8 AD` = 中 |
| GBK | 两字节一组 | `D6 D0` = 中 |

最可靠的一招是**在同一终端里跑两个构建对照**：同一个程序，一个正常编、一个加 `-fexec-charset=GBK`，哪个显示正常，终端就是在按哪种编码解码。

### 最终解法：让编译器输出 GBK

源码继续存 UTF-8，编译时把中文字面量转成 GBK 字节，正好对上终端：

```powershell
gcc number.c -o number.exe -fexec-charset=GBK
```

改完字节从 `E6 88 91…`（UTF-8）变成 `CE D2 BD F1…`（GBK），终端显示正常。

固定下来（已配好，换机器照抄）：

| 用哪种方式编译 | 参数加在哪里 |
| :--- | :--- |
| `F6` / `Ctrl+6` 一键编译运行（C/C++ Compile Run 扩展） | 用户 settings.json 的 `c-cpp-compile-run.c-flags` / `cpp-flags` 末尾加 `-fexec-charset=GBK` |
| `Ctrl+Shift+B` 跑构建任务（tasks.json） | args 数组里加一个 `"-fexec-charset=GBK"` |

```json
"c-cpp-compile-run.c-flags": "-Wall -Wextra -g3 -fexec-charset=GBK",
"c-cpp-compile-run.cpp-flags": "-Wall -Wextra -g3 -fexec-charset=GBK"
```

### 为什么 `chcp 65001` 没用（重要）

直觉是"把终端改成 UTF-8 就好了"，但实测无效：

- `chcp 65001` 只能改**控制台码页**；
- VSCode 集成终端的**解码方式在打开终端那一刻就锁定了**，之后改码页影响不到它；
- 所以会出现怪现象：`chcp` 报告 65001、PowerShell 自己打印的中文正常，但程序输出的中文照样乱码。

结论：**别在终端上折腾，直接让编译器输出 GBK。**

### 两个容易白折腾的坑

1. **快捷键是 F6**（`Ctrl+6` 也行）。`Ctrl+Alt+N` 不触发，`F5` 走的是 Debug。按之前先点一下编辑器。
2. **改完参数可能"看起来没修好"**：扩展有 `skip-if-compiled`，源码不比 exe 新就直接跳过编译、跑旧程序——于是参数改了也还是旧乱码。遇到就删掉 `output\*.exe` 或改一下源码再编。

### 一句话记法

> 源码 UTF-8 不用动，编译时加 `-fexec-charset=GBK`，让程序的字节和终端的 GBK 解码对齐。
